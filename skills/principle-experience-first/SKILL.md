# Experience First

Quando conveniência de implementação conflita com prazer do usuário, escolha o prazer.

- Cada feature, controle e opção precisa se justificar.
- Entregue menos, entregue melhor: experiência polida com três features vence uma tosca com dez.
- Prototipe antes de se comprometer: decisões de design são mais baratas em HTML descartável do que em código de produção.
- Acerte os detalhes: transições, alinhamento, espaçamento, feedback, estados de erro.
- Aperte o loop central: cada feature serve o fluxo principal ou sai do caminho.

O usuário é quem consome o trabalho. Numa UI, o usuário final. Numa biblioteca ou API interna, o colega que a importa. Quem mantém o código depois também é usuário. Pese a experiência deles do mesmo modo e explique impacto do ponto de vista deles.

Fundações servem à experiência. Foundational thinking governa a *sequência* do trabalho; este princípio governa o *alvo*.
