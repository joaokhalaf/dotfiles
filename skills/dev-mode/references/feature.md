# Funcionalidade

1. Derive critérios observáveis do pedido e identifique o fluxo afetado.
2. Defina os dados, contratos e proprietário do estado antes de implementar.
   Compare alternativas somente quando houver uma decisão real de arquitetura.
3. Implemente em partes verificáveis, seguindo convenções existentes e evitando
   abstrações que não resolvam uma necessidade concreta.
4. Execute o caminho principal e os erros relevantes. Use os comandos de teste,
   tipos e lint do projeto quando aplicáveis; valide UI na superfície real.
5. Revise o diff e relate comportamento entregue, validação e limitações.
   Criar PR ou fazer merge depende do pedido, não faz parte automática deste fluxo.
